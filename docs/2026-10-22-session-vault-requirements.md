## 1. 背景

DSH 的「归档会话」是**纯标记**：往 `workspace.json` 的 `global.archivedSessionIds` 里写一个 id，会话文件仍留在
`~/.dsh/sessions/<工作区>/<会话>/session.v4.jsonl.zstd`。本机实测（2026-10-22）：

| 指标 | 数值 |
| --- | --- |
| 已归档会话 | 118 个（as-of 2026-10-22 16:15） |
| 其中仍在磁盘上的 | 118 个（100%，as-of 2026-10-22 16:15） |
| 这些目录合计占用 | 958.6 MB（其中日志文件约 932 MB，as-of 2026-10-22 15:40） |
| 会话根目录总量 | 2.20 GB / 2064 个会话目录（as-of 2026-10-22 15:40；最新读数 2097 个目录，as-of 16:15） |
| v4 日志 / v0 旧格式 | 1564 / 221 |

随之而来的三个现实问题：

1. **磁盘不降**：用户以为「归档」= 收走，实际一个字节没少；958.6 MB 是白占。
2. **扫描不降**：`@kenz1117/dsh-ui-usage-billing` 通过 `sessionPersistence.list()` 全量扫描会话（本机账本 1946 行），归档与否都照扫；启动/打开用量面板都要重读。
3. **管理面缺失**：官方只在侧边栏把归档会话藏起来，没有「归档了多少、占多大、多久没动、能不能搬走、怎么找回」的视图。

现有两个第三方插件（`dsh-archived-sessions` 0.1.5、`@michengai/dsh-archive-manager` 1.1.6）经源码核查**都只做标记层**（只写 `archivedSessionIds`，零文件移动），且 AM 会把「文件不在」判成工件丢失而**删掉归档标记**（`lib/workspace.js` 的 `sessionArtifactMissing` + `pruneUnknownArchivedSessionIds`），与冷存储方向直接冲突。

## 2. 问题（带证据）

### 2.1 归档不释放磁盘、不降低扫描

- 证据：`<DSH_HOME>\storages\workspace.json` → `global.archivedSessionIds` 共 118 项；这 118 个 id 对应的目录**全部存在**，合计 958.6 MB。
- 证据：官方 `dsh-workspace` 的 `archiveSession()` 只向注册表集合追加 id；`unarchiveSession()` 只摘除 id（源码注释原文：`Unarchiving runs no session-existence check`）。

### 2.2 没有冷存储，也没有「归档时间」

- 归档集合是 id 数组、**没有归档时间戳**；阈值按「上次活跃时间」判定，不依赖归档时间。
- 会话目录与工作区记账耦合：118 个归档 id 中 **117 个仍登记在 `workspace.json` 的 `tables.workspaces[].sessionIds`** 里；**这是宿主有意设计（域声明：归档会话保留 sessionIds 槽位以便取消归档还原位置），不是脏数据**。文件搬走后迁移**不动记账**，宿主下次写操作自会按 sessionPath 剪枝（D6′）。

### 2.3 官方全文搜索索引不覆盖冷会话

- 官方搜索是 `@deepseek-ai/dsh-session-query-sqlite`（SQLite FTS5 派生库），其文档明确：对账时会比较持久化快照，**观察到「已删除」的来源就在下次稳定观察时删掉索引行**。
- 结论：会话文件搬走后，内置索引会把它的行删掉——**冷会话必然搜不到**，插件必须自建冷索引。

### 2.4 现有插件都不满足

- `dsh-archived-sessions`：只支持 DSH 0.1.x（peer `^0.1.0-rc.6`）。作为 bundle 安装时在 0.2.1-rc.2 会被版本门**静默跳过**（insert 行可绕过该门，但其仓库 issue #5 已报 inject 门禁静默挂起）；无迁移/恢复/搜索。
- `dsh-archive-manager`：兼容 0.2.1-rc.2，有归档管理 UI（搜索/预览/收藏/批量/修复），但**替换官方侧栏与投影缓存**、侵入性高；且其「工件丢失即删标记」的逻辑会让冷存储的会话被静默取消归档。

## 3. 目标

做一个 **DSH Web 插件** `dsh-session-vault`（显示名「会话保险库」），把「归档」从标记升级为**可配置的冷存储**：

1. **配置页**：设置冷存储根目录、**已归档且上次活跃超过 N 天**自动迁移（默认 14 天）、清扫周期、是否自动迁移。
2. **迁移**：单条 / 批量把已归档会话从 `~/.dsh/sessions` 搬到冷目录，热目录**只留冷索引**（元数据 + 全文索引 + 审计 manifest）。
3. **恢复**：单条 / 批量把冷会话搬回热目录，并恢复为正常（可继续对话）。
4. **搜索**：对冷会话做标题 + 正文全文搜索，返回摘要，可直接预览。
5. **管理 UI**：归档会话列表（热/冷）、搜索、预览、收藏、批量操作、删除（带回收站）、日志诊断与修复。

### 3.1 非目标（本批不做）

- 不修改 DSH 核心、不接管官方侧栏（与 AM 区分）。
- 不做云端同步、跨机器 vault、加密存储（V1 明文落盘，文档明示）。
- 不做向量/语义检索，只做字面全文检索。
- 不迁移未归档会话（提供「归档并迁移」的显式组合动作，但默认不碰）。
- 不做会话合并、导出 ZIP（后续批次）。
- 不承诺在 DSH 运行中热插拔冷盘；盘不可用时降级为只读提示。

## 5. 功能需求

### P1（第一批必交付）

- **FR-1 配置**：冷根目录（默认 `<DSH_HOME>/session-vault/cold`）、`archiveAgeDays`（默认 14；**0 = 关闭自动迁移**）、`autoMigrate`（**默认关**；首次安装为观察模式，用户确认列表后再开启）、`sweepIntervalMinutes`（默认 30）、`dailyBudgetCount`（默认 20 个/天）、`maxConcurrentJobs`（**预留字段**：P2.6 起写入被明确拒绝、本批不生效，写操作恒单串行）、`allowCrossVolume`（默认关；开启需二次确认，**已采纳**）、`hydrateOnUnarchive`（默认开 = 取消归档时透明水合，留开关以便回退，**已采纳**）。`archiveAgeDays` 的语义 = **已归档 + 上次活跃时间超过 N 天**（不是归档时间）。配置存 `<DSH_HOME>/session-vault/config.json`，**保存即生效、无需重启**；冷根目录变更只影响之后的迁移，已迁数据不自动搬。cordis config 仅作首次默认值。
- **FR-2 归档时间追踪与取消归档保护**：包装 `workspaceRegistry.archiveSession` 记录 `archivedAt`（**只在集合进入沿**记，重复点归档不刷新时间）；同时包装 `unarchiveSession` 做**透明水合**（D-16′ 已采纳）——冷会话先搬回热目录再放行官方取消归档，失败即明确报错而不是静默消失（开关 `hydrateOnUnarchive` 默认开，关掉即退回宿主原行为；AM 插件在场时不装包装，降级为 30 分钟差分轮询 + 顶部横幅）。包装只记时间，**不搬移、不建索引**（官方归档按钮不得卡住）。启动时对存量归档 id 回填 `archivedAt`（仅用于展示/排序；**不再作为迁移门槛**）。
- **FR-3 迁移引擎**：单条/批量；同卷用 rename，跨卷（需开启 `allowCrossVolume` **且 UI 二次确认**）用 copy+校验+删除；迁移前校验「已归档 + 非活跃 + 格式在白名单 {0,3,4} + 日志可读 + 目标不存在 + 目录名与 header.cwd 复算的 projectKey 一致」；**迁移前后各算一次全代际 sha256 基线**并写进 marker（崩溃收敛的唯一基准）；**不写工作区记账**（宿主自己会按 sessionPath 剪枝，且归档保留槽位是宿主的有意设计）；冷目录**必须在 sessions 之外**（禁止嵌套）；迁移后写 manifest 与 DB。
- **FR-4 恢复引擎**：**先搬文件回热目录 → 校验 persistence 可见 → 官方取消归档 → 挂回工作区（按 cwd 解析，尽力）**；跨卷用 `.part` → 校验 → rename（多代际按版本升序、最新代际最后），热目录不出现半截代际；搬移失败保持冷态可重试，文件已回但后续失败**不回滚**（记 error + 给「重试完成恢复」入口）。恢复后 DB 行保留，便于再次归档。
- **FR-5 冷索引**：每个会话一行元数据 + 全文（user/assistant 文本，排除 tool 调用/结果/附件/system/request 上下文），迁移时增量写入；支持重建。**P3 例外**：`searchScope=body+toolResults` 时额外收录 `tool/result` 的文本结果（不含参数），默认关。
- **FR-6 列表 API/UI**：合并「热归档（磁盘上）」与「冷归档（vault 里）」；显示大小、时间、状态、错误。
- **FR-7 审计**：`manifest.jsonl` 追加式记录每次迁移/恢复/删除（id、路径、字节数、时间、结果、原因）。
- **FR-14 归档动作**：列表里支持单条/批量「归档」「取消归档」（调官方 `archiveSession`/`unarchiveSession`），
  归档成功后立即记录 `archivedAt` 并可选择「归档并迁移」。

### P2

- **FR-8 自动清扫**：定时扫描归档案，满足「**仍在归档集合里** + **上次活跃超过 N 天** + 非活跃」则迁移；`autoMigrate` 默认关，开启后才跑；阈值为 0 表示关闭自动迁移；有并发上限、**每日预算（默认 20 个）**、失败退避、汇总日志。
- **FR-9 搜索**：**一个显眼的全局面板搜索栏**（面板顶部全宽大输入 + **`Ctrl/Cmd+Shift+K`** 覆盖层（P3 起；普通 Ctrl+K 归宿主）+ 会话头部按钮 + 底栏放大镜）；范围默认正文（用户+助手+标题），可选含工具结果；范围 = **所有工作区的会话（热）+ 归档 + 冷存**，统一自建索引（中文 `Intl.Segmenter`、英文小写），官方全文搜索**不作为依赖**（本机索引库未物化，且对账会删冷行）；结果按会话分组，标注状态（进行中 / 热 / 已归档 / 冷存）与工作区，带 snippet，热会话可直接打开、冷会话可预览/恢复。
- **FR-10 预览**：不恢复即可读取冷日志，渲染最近 N 条消息 / 命中上下文；展示会话元信息。

### P3

- **FR-11 收藏**：本地收藏集合；「按时间」排序时列表置顶，「按工作区」排序（2026-10-28 B4 起的默认）时以收藏 chip 筛选。
- **FR-12 永久删除 + 回收站**：冷会话移入 **`<vaultRoot>/trash/<id>/<ts>/`**（同卷 rename、跨卷 copy+基线校验，失败不删源），可恢复；热会话只 `hidden=1`（文件不动）；显式「彻底删除」才 unlink（仅限 trash 根内，二次确认），30 天到期只提示不自动删。
- **FR-13 诊断与修复**：检测可读性问题（frame-corrupt / extract-empty / index-failed / seq-gap）与 DB/manifest/冷目录对账差异，只读列出；安全修复 = 重新索引 / 标 needs-review / 补删 manifest 行 / 清孤立 marker / 导入冷目录（dry-run 预览 + 逐项确认）；**不做 v0→v4 重编码**（P3-D8 弃做裁定：改会话格式风险高、非插件职责），失败 fail-closed。

### P4（子代理会话冷存，2026-10-27 设计定稿）

口径：把「已结束、未登记、未被引用、≥N 天未活跃」的**子代理会话**（`origin=subagent` 或 `delegationDepth>=1`）整目录搬进冷根；
恢复只搬回热目录，**不碰**官方归档集合。详见[设计档](2026-10-22-session-vault-design.md) §19。

- **FR-P4-1 配置**：`subagentMigrate`（默认 **false**）、`subagentAgeDays`（默认 **14**；0 = 关闭）、`subagentDailyBudgetCount`（默认 50）；保存即生效。
- **FR-P4-2 header 事实扫描**：只读首帧 header，落 `origin / delegation_depth / parent_session`；产出 `subscan:at / count / gaps / orphanEdges`；gaps 非空即暂停（fail-closed）。
- **FR-P4-3 候选与资格**：hot + 子代理 + 未登记 + **无入边引用** + ≥N 天（**含恢复冷却期 `restored_at + N 天`**）+ 非活跃 + 快照新鲜（≤24h），七条全满足才进候选。
- **FR-P4-4 迁移**：复用 marker/全代际 sha256/跨卷 copy+校验+删源；manifest 记 `class=subagent`；`archivedSessionIds` 零改动；迁移后复检失败即搬回。
- **FR-P4-5 恢复**：搬回 → `persistence.stat` → `status=hot`；**不调** `unarchiveSession` / `attachSession`；离线脚本对 class S 跳过 `--write-workspace`。
- **FR-P4-6 对账/列表/暂停分域**：A-13（`cold ⇒ archived`）只约束 class A；`/list` 增 `class` 参数（默认 `archived`）；Sweeper 暂停条件按类分开。
- **FR-P4-7 HTTP**：`subagent-scan` / `subagent-migrate`（必须 `confirm:true`）/ `subagent-job`；`restore` 按 DB 行 class 自动分域。
- **FR-P4-8 UI**：设置页新增「子代理会话冷存」卡（开关/阈值/预算/读数/一键迁移）；面板增「归档会话 / 子代理会话」两个 chip。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 数据安全 | 迁移/恢复全过程可回滚；崩溃后只允许两种**稳定形态**（完整热 / 完整冷）；无法判定时必须收敛为**显式标记态**（needs-review / lost，双份保留、人工处置），不允许出现未标记的第三态 |
| 幂等 | 重复调用、并发调用不产生重复搬移或双份数据 |
| 不阻塞 | 单文件大（数百 MB）时异步分块拷贝并让出事件循环；UI 有进度 |
| 性能 | 百级会话搜索 < 1s；列表页首屏 < 500ms（本地） |
| 隐私 | 全文只落本地 vault；不联网；文档明示明文存储 |
| 兼容 | 0.2.1-rc.2 起已测；0.2.0-rc.1 未测（engines 门跳过）；DSH 升级后不因 schema 变化损坏 |
| 可观测 | 每次动作有日志行；`/session-vault/api/status` 返回队列、最近错误、统计 |

## 7. 验收标准

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| AC-1 | 迁移一个归档会话 | 热目录消失、冷目录存在且字节一致、DB 有行、manifest 有行；重启后 DSH 列表不再出现该会话 |
| AC-2 | 恢复该会话 | 热目录回来、工作区重新挂上、取消归档成功、会话可打开并继续对话 |
| AC-3 | 迁移中途杀进程 | 重启后自动收敛（热完整或冷完整）；无法判定时进入显式 needs-review / lost 并保留双份；无数据丢失，不产生未标记的重复副本 |
| AC-4 | 跨卷迁移中断 | 源目录保留、目标 `.partial` 被清理、DB 状态回到 hot，可重试 |
| AC-5 | 未归档 / 活跃会话 | 永不进入迁移队列（负向断言） |
| AC-6 | 自动清扫 | 只处理「已归档 + 非活跃 + **上次活跃超过 N 天**」的会话（候选必须额外校验 id 仍在归档集合里）；`autoMigrate` 默认关；**`archiveAgeDays = 0` 表示关闭自动迁移，一个都不迁** |
| AC-7 | 全局搜索 | 覆盖所有工作区：热会话命中可打开、归档命中可预览/迁移、冷存命中可预览/恢复；命中正文并返回 snippet；官方索引不可用时仍然可用；首次建索引有进度且可暂停 |
| AC-8 | 内置索引 | 搬家后官方搜索不报错（该会话行被对账删除属预期） |
| AC-9 | 与 AM 共存 | 检测到 `@michengai/dsh-archive-manager` 时警告并暂停自动迁移 |
| AC-10 | 存量迁移效果 | 118 个归档会话全量迁移后：sessions 目录减少约 959 MB（日志约 932 MB）、usage-billing 扫描数减少 118 |
| AC-11 | 冷会话被官方 UI 取消归档 | 透明水合开（D-16′ 已采纳）：文件被搬回热目录且会话可见；若不采纳该方案，则由启动对账发现并在页面横幅提示，**绝不静默消失**（A-13） |
| AC-12 | 插件卸载后手工恢复 | 关 DSH → 跑 `tools/vault-restore.mjs` → 起 DSH：会话在侧栏可见且可继续对话（I-10 的可执行演练） |
| AC-P4-1 | 子代理会话迁移 | 满足资格的子代理会话整目录进冷根：热目录消失、字节一致、DB `status=cold`、manifest `class=subagent`；**`archivedSessionIds` 零改动** |
| AC-P4-2 | 被引用保护（负向） | 任何被 `parentSession` 指向的子代理会话永不迁移（本机 15 个实测样本全部拒绝） |
| AC-P4-3 | 恢复 | 搬回热目录、`status=hot`、可被搜索/预览；**不调用** `unarchiveSession`/`attachSession`，侧栏不出现该会话 |
| AC-P4-4 | 快照缺口（负向） | `subscan:at` 缺失或 >24h、或 gaps 非空 ⇒ 零搬移 + UI 明确暂停原因 |
| AC-P4-5 | 与 class A 隔离 | 子代理冷行不被标 `external-unarchived`；class A 的清扫/列表/恢复口径不变（回归全绿） |
| AC-P4-6 | 规模验收 | 本机 ≥14 天候选 1271 个 / 555 MB 全量迁移后：sessions 目录 2414 → 约 1143，占用 2301 MB → 约 1746 MB（**as-of 2026-10-27 16:17，口径见设计档 §19.1**） |

## 8. 风险与开放问题

| 编号 | 问题 | 影响 | 处理 |
| --- | --- | --- | --- |
| R-1 | 搬走文件后，工作区记账（`sessionIds`）留下空指向 | 可能产生幽灵条目或启动告警 | **v0.3 已裁定：插件不写记账**（宿主 `mutate()` 会按 sessionPath 自行剪枝，且域注释明写「归档会话保留它的 sessionIds 槽位」）；恢复时 `attachSession` 为尽力调用、失败只提示不阻断；另交付 `tools/vault-restore.mjs` 供卸载后手工恢复（I-10） |
| R-2 | 投影缓存残留 | 已核实为 per-record、无「全表列会话」，**不会**产生幽灵会话，只留孤儿缓存垃圾 | 不处理（可选清理） |

| R-7 | 会话身份=路径：文件路径必须等于 `generationLogPath(root, header.cwd, id)` | 放错 projectKey 会让 `persistence.list()` 抛错，进而可能拖垮启动 | 迁移前校验复算一致；冷目录禁止在 sessions 之下；恢复按 header.cwd 复算 |

## 9. 本批交付边界
