- 日期：2026-10-22
- 关联：[设计档](2026-10-22-session-vault-design.md)（v0.4.2） · [需求档](2026-10-22-session-vault-requirements.md)（v0.4.1）
- 回答的问题：**会不会影响 workspace-scan、workspace-intel、workspace-agent 这三个工作区？**

## 0. 结论（先说人话）

- **工作区目录不会被碰**：插件只读写 `~/.dsh/sessions` 下**已归档会话的会话目录**，你的 `<workspace-root>\*` 项目文件一个字节都不动（I-1 + A-19 假 fs 前缀白名单测试）。
- **未归档的普通会话不会被搬、不会被写**：它们不在 class A 迁移候选里（I-2 仅约束 class A）；**但全量搜索索引会只读它们的日志**（FR-9 覆盖所有工作区会话）。子代理会话按 I-15 另行判定（P4）。
- **默认不会自动迁移**：`autoMigrate` 默认关（首次安装 = 观察模式）。但按「已归档 + 上次活跃 > 14 天」的口径，存量里**已有 48 个（282.8 MB）满足条件**——一旦你开启自动迁移，首轮就会按日预算（默认 20 个/天）开始搬；搬前可在列表里先审阅。
- **被搬走的会话可恢复**：整目录原样搬到冷目录（同卷 rename），marker 记全代际 sha256 基线，manifest 记路径与校验；恢复 = 搬回原位置 → 校验 → 官方取消归档 → 挂回工作区（尽力）。
- **子代理会话（P4 已实施并实机迁移 2026-10-28：class S 冷存 1156 个）**：只搬「未登记 + 未被引用 + ≥N 天未活跃」的那部分；恢复只搬回 + `status=hot`，**不调** `unarchiveSession`/`attachSession`（I-16）；资格/快照任一不满足就一个都不搬（fail-closed）。
- **不锁定在插件里**：冷目录结构与热目录同构，manifest 是纯文本；即使插件被卸载/损坏，也可用 `tools/vault-restore.mjs`（关 DSH 后跑）手工搬回并写回记账，再在官方 UI 取消归档（I-10 是可执行演练，不是口头承诺）。
- **会诊新发现的一个真实风险（四方独立收敛）**：官方「取消归档」不做存在性检查——冷会话若被外部取消归档，会变成「既不在热目录、也不在归档列表、谁也看不见」的僵尸。这不是丢文件，但用户感知等于丢。对策：不变量 I-11 + 拦截 A-13 + 启动对账 + 一键恢复（行为方案 D-16′ 已由用户 2026-10-23 裁定采纳）。

## 1. 数据不变量（每条都要有测试锚）

| 编号 | 不变量 | 违反时的后果 | 锚 |
| --- | --- | --- | --- |
| I-1 | 插件**从不写入** `<workspace-root>\*` 或任何工作区目录 | 项目文件被污染 | A-19（假 fs 前缀白名单） |
| I-2 | **class A 专用**：只有 `archivedSessionIds` 里的 id 才可能进入 class A 迁移队列（class S 的资格见 I-15；两类互斥，见设计档 §19） | 未归档的普通会话被搬走 | A-2（负向）/ A-P4-1 |
| I-3 | 活跃（live / 有运行中回合）会话永不迁移 | 运行中的会话被抽走 | A-2 |
| I-4 | 迁移前必须通过「目录名 == `projectKey(header.cwd)`」校验 | 搬回时 `persistence.list()` 抛错 | A-10 |
| I-5 | 搬迁是**整目录**操作，全代际文件清单/sha256 与 **marker 基线**一致，manifest 记一行 | 丢文件或半目录 | A-1 / A-6 / A-15 |
| I-6 | 迁移**后**复检：若 id 已不在归档集合或出现 live 会话 → **立即搬回** | 竞态把热会话搬走 | A-12 |
| I-7 | 恢复顺序固定：搬回 → 校验 `persistence.stat` → 官方 `unarchiveSession`（原件）→ `attachSession`（尽力） | 出现打不开的幽灵条目 | A-4 / A-17 |
| I-8 | 永久删除只对冷存储提供（P3），先移入 `<vaultRoot>/trash/<id>/<ts>/`；热会话只 `hidden=1`，文件不动 | 误删无法挽回 | A-P3-4 / A-P3-7 |
| I-12 | **purge 是全设计唯一不可逆 unlink**：必须 `confirm:true` 且目标 resolve 后位于 trash 根内；否则零写入 | 删除越界 | A-P3-7（负向） |
| I-13 | `hidden=1` 的会话**不进清扫候选、不自动迁移** | 用户以为已删却被搬走 | A-P3-4（负向） |
| I-14 | 工具结果入库 = **明文**（可能含密钥）：`searchScope` 默认 body，开启需用户显式操作并在设置页提示 | 隐私泄漏 | A-P3-2 + 设置页文案断言 |
| I-9 | 冷目录必须在 `~/.dsh/sessions` 之外 | 可能拖垮 DSH 启动 | A-11 |
| I-10 | 插件卸载后，冷数据仍可手工恢复（目录同构 + manifest 纯文本 + `tools/vault-restore.mjs`） | 数据被锁死在插件里 | 演练：关 DSH → 脚本 → 起 DSH → 会话可见可继续对话 |
| I-11 | **cold ⇒ id ∈ archivedSessionIds**：冷会话永远同时处于归档集合 | 官方 UI 把冷会话取消归档 → 谁也不可见的「隐形僵尸」 | A-13（拦截/对账 + 一键恢复） |
| I-15 | 子代理会话只有同时满足「未登记 + **无入边引用** + ≥N 天未活跃 + header 可读 + 扫描快照新鲜」才可能进迁移队列 | 把父会话的 lineage 拆断（`traceSession` 变 partial） | A-P4-1 / A-P4-2（负向） |
| I-16 | class S 恢复**不得**调用 `unarchiveSession` / `attachSession`，只搬回 + 校验 + `status=hot` | 幽灵归档 / 幽灵挂载 | A-P4-7（负向） |
| I-17 | `cold ⇒ id ∈ archivedSessionIds`（I-11）**只约束 class A**；class S 冷行永不参与 A-13 判定 | 每次启动把整台清扫器锁死 | A-P4-8（负向） |
| I-18 | 子代理迁移的「谁引用谁」必须来自新鲜快照（≤24h 且 gaps=0）；快照不可信时零搬移 | 引用竞态搬断 lineage | A-P4-5（负向） |

## 3. 时间线：什么时候会发生什么

| 时间点 | 会发生什么 |
| --- | --- |
| 插件安装当天 | 只建空索引与配置；`autoMigrate` 默认关，0 个会话被搬；列表标出 48 个「可迁移」 |
| 你开启自动迁移后 | 每 30 分钟一轮，按「归档 + 闲置 >14 天 + 非活跃 + 校验通过」迁移，日预算默认 20 个 |
| 任意时刻 | 你手动勾选「立即迁移」才会提前搬；「恢复」随时可用 |
| 恢复之后 | 文件回原 projectKey，官方取消归档，工作区重新挂上（尽力），可继续对话 |

## 4. 会不会丢？唯一可能丢数据的路径

| 场景 | 结果 | 缓解 |
| --- | --- | --- |
| 插件崩溃在搬移中途 | 收敛为「热完整」或「冷完整」；无法判定 → **显式** needs-review / lost（双份保留） | 启动对账、marker 全代际 sha 基线 |
| **跨卷迁移「删源瞬间会话被追加写入」** | **本设计唯一有真实丢帧窗口的分支**（copy 完成 → 删源之间的 TOCTOU） | copy 前后双指纹 + 删源前临界区复检；默认同卷，跨卷需显式开关 + 二次确认（已采纳） |
| 冷盘拔出/权限变化 | 只读降级，不删除任何标记与文件 | fail-closed |
| 你手工删了冷目录 | 该行标记 `lost`，不自动删任何东西 | 不自动清理 |
| 插件被卸载 | 冷数据原样保留，可按 manifest 手工搬回 | 结构同构 + 纯文本 manifest + vault-restore.mjs |
| 误点永久删除（P3） | 先进回收站，可还原 | 二次确认 + 回收站 |
| 冷会话被官方 UI 取消归档 | **会话隐形（不是丢文件）**，靠 A-13 兜底找回 | 包装透明水合（D-16′ 已采纳）+ 启动对账 + 横幅一键恢复 |

**真正会丢数据的只有一种**：用户在冷目录外手工删除文件。插件自身的设计原则是「任何失败都不删源」。

## 5. 恢复保证（超过 14 天被搬走的会话）

顺序与失败策略**以设计档 §7 为唯一权威**。用户向摘要：搜索/预览 → 点「恢复」→ 插件按落库事实搬回原 projectKey → `persistence.stat` 校验 → 调官方 `unarchiveSession` 原件 → 尽力挂回工作区 → 会话可继续对话。

任一步失败：文件已回热态后**不回滚**（幂等续跑，从最后持久步继续），错误显示在列表，可重试。
找不到原工作区：文件已回磁盘原位 + 已取消归档，提示「重建工作区后重试挂回」（BL-3）。
